# 业务约定

capacity 为同一场次同时接待人数，不允许跨时段挪额。booking 以 party_id 为团体，participants 是当前预约人数，cancelled_count 为累计取消，不重复累加重传记录；revision 单调决定版本，actual_count 在场次闭场后有效，未成熟留空。风险容忍度 alpha 表示超容量概率上限；只有声明并通过历史校准的概率分布可使用概率结论，否则用界限或明确不支持。reservation_type=public_benefit 的 protected_capacity 在 release_at 前不可销售，confirmed 人数永久进入承诺直到正式取消。waitlist 按 submitted_at 优先，在同一优先级可比较不同可行组合但不能跳过可完整接受的更早团体。compensation_per_person 和 compensation_budget 限制超员方案。售停区间列于 sales_controls，不是需求为0。

bookings 的同 booking_id 多 revision 是完整替代记录，不将其人数相加；同 party_id 可跨场预约，相关性分析不得以 booking_id 冒充独立访客。尚未发生闭场的 actual_count 即使缺失也不补0。session_id 的日期是接待日，submitted_at 是预约发起时间，观察截止之后的实际信息不可提前使用。任何已接受的新预约都必须从同场次真实剩余额度继续，decision 不自动撤回订单。

所有 date 或 at 字段按其声明的当地日期或带时区时间解释，缺失值为 JSON null，空列表表示明确为空。记录编号只标识实体，不包含优先级。涉及历史截点时仅使用该截点已知事实，生效期间与获知时间分别按相应字段解释。不同情景不等于已经确认的实际业务操作。
